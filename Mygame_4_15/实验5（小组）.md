# <font style="color:#117CEE;">二、实验原理：</font>
## 系统设计框架
本实验采用“传感器采集 + 串口传输 + PC游戏解释执行”的三层架构，整体流程如下：

1. 硬件采集层（Arduino）
+ 超声波模块 HC-SR04 负责检测前方距离，TRIG 接 D9、ECHO 接 D10。
+ 光敏模块 AO 接 A0，采集环境亮度。
+ I2C 1602A LCD（常见地址 0x27/0x3F）用于本地显示分数。

2. 通信层（USB 串口）
+ Arduino 向 PC 周期发送 3 列数据：`distance_cm,light_value,jump`。
+ Python 向 Arduino 回传分数命令：`S<score>`（例如 `S123`），用于 LCD 实时刷新。
+ 波特率使用 115200，降低交互延迟。

3. 应用层（Python + Pygame）
+ `app/game.py` 自动扫描串口并连接 Arduino；若未连接则退化为键盘模式。
+ 对 Arduino 的 `jump` 脉冲直接映射为游戏跳跃输入。
+ 根据光敏值做带滞回和连续确认的昼夜切换，减少误触发。

核心控制理论：

+ 距离测量：通过超声波飞行时间换算距离，`distance = duration * 0.034 / 2`。
+ 抗抖策略：一阶低通滤波 `filtered = 0.4 * filtered + 0.6 * distance`，抑制瞬时噪声。
+ 跳跃触发：采用“近阈值触发 + 远阈值复位 + 防抖时间窗”，即当距离小于 `JUMP_OBSTACLE_NEAR_CM` 且满足 `JUMP_DEBOUNCE_MS` 时发出一次 `jump=1` 脉冲；回到 `JUMP_OBSTACLE_FAR_CM` 以上后允许下一次触发。

该设计将“连续模拟量”转换为“稳定离散事件”，可有效提升体感控制可玩性和复现性。





## 实验结果与分析
实验结果：

1. 串口通信结果
+ PC 端可稳定接收 Arduino 数据帧，格式为 `距离,光敏,跳跃脉冲`。
+ Arduino 可稳定接收 Python 下发的 `S<score>` 命令并刷新 LCD 第二行分数。

2. 交互功能结果
+ 使用手掌或物体靠近超声波传感器时，小恐龙可触发跳跃。
+ 光照降低后，游戏自动切换夜间模式；光照恢复后自动回到白天模式。
+ 未连接 Arduino 时，程序可回退到键盘控制，保证程序鲁棒性。

3. 参数调优结果
+ 将近阈值调整为 18cm、远阈值 28cm 后，触发成功率明显提高。
+ 防抖时间 180ms 可有效避免短时间重复跳跃。
+ 采样间隔约 15ms，响应速度满足实时游戏需求。

分析：

+ 影响控制稳定性的主要因素是传感器噪声与手势速度。通过低通滤波与双阈值机制，系统在“灵敏度”和“抗抖动”之间取得较好平衡。
+ LCD 的加入实现了“PC界面 + 外设界面”双通道反馈，增强了人机交互体验。
+ 项目完成了从“传感器数据采集”到“上位机应用行为映射”的完整闭环，满足实验目标。

# <font style="color:#117CEE;">三、总结与反思</font>
##  特色工作
本组特色工作体现在“稳定交互”而非单一功能实现：

1. 采用“低通滤波 + 双阈值 + 防抖”的组合策略，将超声波连续测距转化为稳定跳跃脉冲，避免了常见的连跳与误触发。
2. 设计双向串口协议：Arduino 上报传感器状态，Python 回传分数，实现游戏与外设显示联动。
3. 加入 I2C 地址自动扫描与兼容处理（0x27/0x3F + 全范围扫描），提升了不同 LCD 模块的适配性。
4. 软件上保留键盘后备输入，硬件异常时系统仍可运行，增强了工程可用性。



## 反思
实验中出现的主要问题是：不同实验箱中的 LCD1602A I2C 地址不一致，且开发环境可能缺少 `LiquidCrystal_I2C` 库，导致“无显示或编辑器报错”。

解决办法：

1. 在 Arduino 端先扫描 I2C 总线，优先尝试 0x27/0x3F，再进行全地址扫描，自动选择可用地址。
2. 在工程代码中加入 `__has_include` 条件包含与兜底声明，保证编辑器阶段不因缺库出现大量误报。
3. 联调时通过串口日志同步检查 I2C 扫描结果、数据帧格式与分数回传，逐步定位问题。

反思：后续可增加“串口可视化调参面板”，把阈值和防抖参数在线可调，进一步减少现场调试时间。
